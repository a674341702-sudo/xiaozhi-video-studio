# 中文 AI 配音候选评估：MOSS-TTS-Nano

更新日期：2026-11-28  
状态：**候选研究，未集成，未通过中国大陆网络与安卓真机验收**

## 初步结论

MOSS-TTS-Nano 值得继续做独立实验，但目前不能直接放进小智视频正式工作流。它有 ONNX CPU 和浏览器方向的实现，也提供 Android ONNX Runtime 示例；然而“模型参数约 1 亿”不代表下载包只有 100 MB。官方模型仓库包含多个 ONNX 图和外部权重文件，单个权重文件已经达到数百 MB 级别。模型与音频 tokenizer 还需要配套下载。

## 已核实的技术事实

- 官方源码仓库：https://github.com/OpenMOSS/MOSS-TTS-Nano
- 官方 ONNX 模型卡：https://huggingface.co/OpenMOSS-Team/MOSS-TTS-Nano-100M-ONNX
- 官方仓库说明 ONNX CPU 推理不需要 PyTorch，并提供 onnxruntime / onnxruntime-web 方向；模型缺失时，默认流程会从 Hugging Face 下载 TTS 模型和音频 tokenizer。
- 官方 Android 示例：examples/android_onnx_runtime。示例刻意保持最小化，模型文件放在 APK 外部；演示使用预先 token 化的短文本。自定义文本还需要 SentencePiece 兼容实现或预处理步骤，因此它不是可直接嵌入产品的完整 Android TTS 模块。
- 官方仓库/模型卡标示 Apache-2.0；集成前仍须保留许可证与第三方依赖声明。
- Hugging Face 页面列出的 moss_tts_local_shared.data 单个文件大小为 230 MB。另一个镜像页面列出的 global shared 文件为 441 MB；该镜像不是官方国内分发渠道，不能当作国内可用性证明。
- 模型推理还依赖 MOSS-Audio-Tokenizer-Nano-ONNX。必须把 tokenizer 的完整文件清单、体积、许可证和实际加载要求一并纳入评估，不能只算 TTS 主模型。

## 当前阻塞项

1. **国内下载来源未验证**：尚未确认官方模型及配套 tokenizer 存在稳定、可合法使用的中国大陆镜像或免费托管方案。禁止客户端首次运行时请求 Hugging Face。
2. **手机资源开销未知**：尚未在目标 Android 手机测量下载总量、峰值内存、CPU 占用、合成耗时、发热和连续生成稳定性。
3. **浏览器端集成未验证**：需要确认 ONNX Runtime Web 的实际模型输入输出、外部权重加载、WASM/WebGPU 兼容性，以及目标浏览器内存限制。
4. **Android 示例不等于网页集成**：官方 Android 示例是原生 ONNX Runtime smoke test；自定义中文文本还需补齐 tokenizer 路径。不能把它描述成现成的浏览器组件。
5. **语音质量未实听**：必须用真实中文商家文案试听，检查普通话自然度、数字/地址/菜名读法、断句和语速。

## 小智视频的集成门槛

只有全部满足以下条件，才进入产品工作流：

- 找到可核验、普通中国大陆网络可稳定访问的模型与 tokenizer 下载来源；无海外回退。
- 完整列出所有模型文件、总下载量、SHA-256 校验值、许可证与依赖。
- 模型按需下载，显示总大小/进度，支持暂停、继续、失败重试和删除；默认不自动下载数百 MB 文件。
- 在目标 Android 手机和 Chrome/微信浏览器分别完成模型加载与合成测试。
- 验证中文文本前处理、语音输出采样率、音量、WAV 编码和现有视频配音轨兼容。
- 生成失败时明确提示，并保留手机录音/上传音频备用路径。
- 不新增未经用户同意的收费 API、云服务器、对象存储或流量费用。

## 下一步实验顺序

1. 先研究官方 browser ONNX manifest、运行时输入输出和完整模型文件清单，不下载大模型。
2. 核对配套 tokenizer 模型文件及体积，检查是否有可信国内分发源。
3. 如果国内来源仍未确认，暂停网页端集成，继续保留录音备用方案。
4. 只有下载来源和设备资源评估通过后，才建立独立 TTS 实验页；不影响当前视频生产线。

## 产品文案边界

当前可说：“支持生成配音稿、手机录音和导入已有中文配音文件。”

当前不可说：“已经支持自动 AI 配音”“无需网络即可直接生成普通话”“已通过中国大陆网络测试”。
